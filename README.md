# Бот 4-дневного марафона · метод «ФИНИШ»

Telegram-бот, который ведёт человека по бесплатному марафону Павла Андреева:
кружки, отзывы, записи четырёх дней, опросники между днями и кнопки покупки
в конце. Сделан по ТЗ от 30.08.2026.

## Быстрый запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить токен и чаты
python -m bot.main
```

Без заполненного `.env` бот не стартует и скажет, чего не хватает — это
намеренно: бот без чата покупок потеряет первую же заявку.

## Что нужно от заказчика для запуска

| Что | Зачем |
|-----|-------|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `PURCHASE_CHAT_ID` | группа, куда падают заявки на покупку |
| `SUPPORT_CHAT_ID` | группа службы заботы |
| `ADMIN_IDS` | кто может грузить записи дней и пользоваться всеми командами |
| `STATS_IDS` | кому открыта только статистика: `/stats`, `/кто`, `/ссылки`, `/status` (через запятую; необязательно). Из чатов сводки, поддержки и заявок эти команды работают у всех участников и без списка. Чужая команда в личке не уходит в заботу — бот отвечает, что доступа нет, и показывает id человека. Числа — через запятую, пробел или точку с запятой, кавычки не мешают; @ник не подходит. После правки в Railway нажать «Deploy» — пока изменения не применены, бот их не видит. Что бот реально прочитал, показывает `/status` в строках «Доступ» |
| Записи 4 дней | видео марафона (лежат у Алексея в Zoom) |
| `SITE_BOT_START_URL` | необязательно. Куда сообщать первый запуск по ссылке с сайта спортзала, чтобы сайт отдал его в рекламу Meta. По умолчанию `https://energy-sport-gum.ru/api/bot-start`; пустое значение выключает. Сайт дописывает в ссылку код клика (`site_fb--k3v9x0a1b2c4`), бот отрезает его до разбора источника, уходит только код (`bot/launch_report.py`) |

Чтобы узнать ID группы: создайте её, добавьте бота администратором, напишите
туда любое сообщение и перешлите его боту [@getmyid_bot](https://t.me/getmyid_bot).
ID группы отрицательный, вида `-1001234567890`.

## Куда заливать записи дней

Это вопрос из ТЗ, вот ответ. **Проще и надёжнее всего — в сам бот.**

Отправьте боту видео дня с подписью `day1` (или `day2`, `day3`, `day4`).
Бот запомнит его и дальше будет рассылать людям мгновенно.

Почему так:

- **Нет ограничения по размеру.** Бот не перезаливает файл, а отправляет
  ссылку на уже лежащий в Telegram — размер значения не имеет.
- **Человек не уходит из Telegram.** Не нужен ни YouTube, ни браузер;
  досмотры выше, ссылку не перешлёшь постороннему одним нажатием.
- **Ничего не платим** за хранение и трафик.

Загрузить видео в Telegram может любой аккаунт: до 2 ГБ, с Premium до 4 ГБ.
Если день длиннее — режем на части и грузим `day1` частями по очереди.

**YouTube «по ссылке» брать не советую:** в России он ощутимо замедлен, а
аудитория марафона в основном российская — часть людей просто не досмотрит.
Если всё же нужен внешний сервис (например, ради статистики досмотров) —
подойдёт Kinescope или VK Видео, бот умеет отправлять и ссылку:

```
day1 https://kinescope.io/xxxxx
```

## Записи уже лежат на сайте

Пока записи не залиты в бот с аккаунта, они отдаются страницами сайта
энергетического спортзала — файлы на том же VPS, ключ доступа в
`/etc/gym.env` (`MARATHON_KEY`), без него страница отдаёт 404:

```
day1 https://energy-sport-gum.ru/marathon/1?k=<ключ>
day2 https://energy-sport-gum.ru/marathon/2?k=<ключ>
day3 https://energy-sport-gum.ru/marathon/3?k=<ключ>
day4 https://energy-sport-gum.ru/marathon/4?k=<ключ>
```

Четыре сообщения боту — и дни уходят людям ссылкой. Когда записи зальют
в телеграм (видео с подписью `day1`), бот переключится на них сам: видео
в базе имеет приоритет над ссылкой.

## Как устроена воронка

| Шаг | Когда | Что уходит |
|-----|-------|------------|
| До /start | — | приветствие заказчика стоит в описании бота на пустом экране, над кнопкой «Старт» (бот задаёт его через API при запуске) |
| /start | сразу | короткое «Поехали!» с кнопкой службы заботы под полем ввода; воронка стартует сразу, без «Запустить» |
| Приветствие | сразу | приветственный кружок Павла (две части) |
| Отзывы | +60 сек | лента: 4 картинки-сторис и 5 видеоотзывов вперемежку, каждые 2 секунды (`media/reviews`, шага без файла нет — он пропускается) |
| **День 1** | сразу за отзывами | запись + текст про ПРЕДНАЗНАЧЕНИЕ |
| Опросник 1 | +150 минут | кружок «посмотрел первый день?» + Да/Нет |
| **День 2** | +5 сек после кружка ветки | запись + текст про ОТНОШЕНИЯ |
| Опросник 2 | +120 минут | кружок «посмотрел второй день?» + Да/Нет |
| **День 3** | +30 сек после кружка ветки | запись + текст про ЗДОРОВЬЕ |
| Опросник 3 | +120 минут | кружок + Да/Нет |
| **День 4** | +3 сек после кружка ветки | запись + текст про ФИНАНСЫ |
| Продажа | +60 минут | кружок, через 2 сек кнопки покупки, следом кружок про заботу |

Весь путь — 7 часов 30 минут. Человек, начавший в 10 утра, доходит до кнопок
покупки к вечеру того же дня, и ни один шаг не приходится на ночь.

Ответы «Да» и «Нет» ведут к одному и тому же дню, но с разными кружками —
как в ТЗ. **Пока человек не нажал «Да» или «Нет», следующий день не приходит**
(Павел 17.09.2026). До этого через 12 часов бот сам вёл по ветке «Нет»; вернуть —
`POLL_FALLBACK_HOURS` в `bot/config.py` (переменная окружения больше не читается).
Не ответившим на первый вопрос через 5 часов после запуска приходит дожим.

## Команды администратора

| Команда | Что делает |
|---------|------------|
| `/status` | что загружено, чего не хватает, сколько людей и заявок |
| `/test` | прогнать всю воронку на себе за ~10 минут (паузы сжаты в 60 раз) |
| `/resend 1` | дослать запись дня 1 тем, кому она ушла без записи (так же 2, 3, 4); `/resend 1 всем` — всем, кто этот день уже прошёл |
| `/stats` | подробная статистика разделами с кнопками: сводка, воронка, источники, дни и опросы, по времени, покупки, где люди сейчас; периоды — сегодня, 7 и 30 дней, всё время. `/stats csv` или кнопка «Все люди таблицей» — выгрузка для Excel |
| `/кто` | поимённо, кто заходил в бота, откуда и запустил ли (`/кто 50` — больше строк) |
| `/ссылки` | готовые ссылки с метками, чтобы вставить в рассылку |
| `/написать 391182739 текст` | написать человеку от имени бота по ID или `@нику` (также `/write`). Без текста бот спросит, что отправить, — тогда реплаем уходят и фото, и голосовые. Доступно всей команде (админы, `STATS_IDS`, получатели заявок); писать можно только тем, кто сам запускал бота |
| `/чс` | чёрный список с историей; `/чс 391182739` или `/чс @ник` — внести, `/разбан 391182739` — убрать (также `/ban`, `/unban`). Быстрее — кнопка «🚫 В чёрный список» под уведомлением о человеке (запуск, «Написали в бота», заявка на покупку), с подтверждением. Человек из списка: марафон снят, его сообщения и кнопки бот не принимает, команде они не приходят; в каналах и чатах Павла, где бот админ с правом «Блокировка пользователей», — бан (чаты бот запоминает сам, когда его назначают админом). В /stats — раздел «Чёрный список», в таблице — колонка. Команду проекта внести нельзя |
| `/пульт` | открыть пульт — переписки со всеми в одном окне (также `/panel`), см. ниже |
| `/live` | вернуть себе боевые сроки и очистить свою очередь |
| `/help` | памятка по загрузке материалов |

Загрузка материалов — просто отправить боту:

- видео с подписью `day1`…`day4` — запись дня;
- текст `day1 https://…` — ссылка вместо видео;
- фото или видео с подписью `review1`…`review9` — подменить шаг ленты
  отзывов (1, 3, 5, 7 — картинки, остальные — видеоотзывы). Без подмены
  лента берётся из `media/reviews`: `img1-4.jpg` — четыре сторис с отзывами
  (рендер `gym-landing/tools/reviews.html`), `vid1-5.mp4` — видеоотзывы
  заказчика; их кладут в папку и коммитят, бот подхватит. Отзыв-кружок
  (экспорт видеосообщения из Telegram) кладут как `vidN.note.mp4`,
  вырезанным в квадрат, — он уйдёт видеосообщением, а не видео. Лимиты
  Telegram на видеосообщение от бота: файл до 12 МБ, а длиннее минуты он
  сам превращает его в обычное видео — такие оставляем `vidN.mp4`.
  После замены роликов запустить `python tools/reviews_meta.py`: он пишет
  размеры и длительность в `media/reviews/meta.json`, без них Bot API
  показывает видео квадратной заглушкой («отзыв какой-то кривой»).
- Записи дней уходят с обложкой `media/intro/coverN.jpg` — превью дня,
  где энергия идёт в сферу (последний кадр заставки). Обложки пишет
  `tools/days.py` при сборке записей.

## Пульт админа (18.09.2026)

Мини-приложение внутри Telegram: одно окно, где видны все, кто заходил
в бота, и переписка с каждым. AleX 17.09.2026: «чтобы тыкал на человека —
и открывался диалог с ним».

Что умеет:

- список людей — свежая переписка сверху, рядом цифра «ждёт ответа»;
- поиск по нику, имени или ID — кусочком, без точного совпадения;
- диалог: вся переписка и поле ввода — сообщение уходит от имени бота;
- чёрный список кнопкой прямо из диалога (и обратно);
- под уведомлениями о человеке появляется «💬 Ответить в пульте» —
  открывает сразу его диалог;
- **«Выбрать»** в шапке списка — галочки у людей и «Написать» внизу:
  одно и то же уйдёт каждому отмеченному отдельным сообщением, с обычным
  уведомлением. Работает всё то же — текст, вложение ссылкой, голосовое,
  кружок. За раз до 200 человек; дальше это уже рассылка (`/рассылка`),
  у неё свой доклад о ходе и продолжение после перезапуска.

Кому ещё можно написать пачкой, не открывая пульт: `/рассылка @ник1 @ник2`
— бот попросит сообщение и покажет, скольких нашёл. Без ников — всем.

Кто может войти: только команда проекта (`config.is_team`). Пароля нет:
Telegram подписывает каждый вход токеном бота, и подпись проверяется
на каждом запросе (`bot/web.py`, `check_data`).

Чтобы включить на бою:

1. В Railway у сервиса бота — Settings → Networking → **Generate Domain**.
2. Туда же в Variables добавить `WEBAPP_URL` с этим адресом (с `https://`).
3. Перезапуск — и `/пульт` покажет кнопку.

Без `WEBAPP_URL` бот работает как раньше, а `/пульт` честно говорит,
что пульт не включён.

Посмотреть пульт локально, без Telegram и без боевой базы, можно
демо-запуском — см. `webapp/` и `bot/web.py`.

## Источники: откуда пришёл человек

AleX 07.09.2026: «кто и из какого источника перешёл в бота — что из
телеграма, что из инстаграма, что из фейсбука». Источник — хвост ссылки
на бота; Telegram отдаёт его первым сообщением `/start ig`, бот
запоминает его за человеком (первый непустой, повторный /start по другой
ссылке не переписывает). Ссылки для размещения:

| Где стоит ссылка | Ссылка |
|---|---|
| Instagram (шапка, сторис) | `https://t.me/finish_marafon_bot?start=ig` |
| Facebook / реклама Meta | `https://t.me/finish_marafon_bot?start=fb` |
| Telegram (канал, посты) | `https://t.me/finish_marafon_bot?start=tg` |
| YouTube | `https://t.me/finish_marafon_bot?start=yt` |
| ВКонтакте | `https://t.me/finish_marafon_bot?start=vk` |
| TikTok | `https://t.me/finish_marafon_bot?start=tt` |

Сайт спортзала ставит метку сам: `site`, а если человек пришёл на сайт с
рекламы с utm_source или fbclid — `site_fb`, `site_ig`
(`js/analytics.js` лендинга). Любая другая латинская метка тоже
принимается и показывается как есть.

**Своя метка на каждую рассылку (AleX 09.09.2026).** В телеграме идёт
несколько рассылок разом, и нужно понять, какая работает. Для этого к
`tg` через подчёркивание дописывают любое имя — латиницей, цифрами, без
пробелов:

    https://t.me/finish_marafon_bot?start=tg_1
    https://t.me/finish_marafon_bot?start=tg_storis5
    https://t.me/finish_marafon_bot?start=tg_kanal

В сводке они встанут отдельными строками: «Telegram ← 1», «Telegram ←
storis5». Готовые ссылки бот выдаёт сам по команде `/ссылки`.

Смотреть: `/stats` в боте (сегодня, 7 дней, всё время) или почасовая
сводка в чат — переменная `STATS_CHAT_ID` (создать группу, добавить
бота, ID как у чата заявок). В начале каждого часа по Москве бот пишет,
сколько пришло и откуда; пустые часы молчат.

`/stats` показывает не только «пришло», но и весь путь каждой ссылки:
сколько запустили марафон, сколько отвечали на опросники, сколько дошли
до конца (ответили на опросник третьего дня) и сколько нажали кнопку
покупки. Сравнивать рассылки по одному «пришло» бесполезно: та, что
привела вдвое больше людей, может не дать ни одного дошедшего.
Поимённый список — `/кто`.

Каждый новый запуск марафона сразу уходит сообщением «Новый запуск марафона»
лично команде — тем же людям, что получают заявки на покупку (Павел, AleX и
`PURCHASE_CHAT_ID`), и в чат `ENTRY_CHAT_ID`, если он задан (пусто — в чат
сводок `STATS_CHAT_ID`): имя ссылкой на профиль, ник, id, время, откуда
пришёл и в который раз запускает. До 14.09.2026 уведомления шли только в
чат, а он не был задан, — и никуда не приходили. Пришедший по
заявке с сайта — с её номером (AleX 11.09.2026). Номер заявки виден и в
`/кто`, и в выгрузке таблицей: по нему человек из бота сверяется с заявкой
на сайте — в отчёте посещений сайта имён нет, там по нику не найти.

## Подробная статистика (11.09.2026)

Sharp: «статистика в боте маленькая, сильно расширь». Раньше бот знал
только «пришёл» и «запустил», а дальше был слеп. Теперь:

- **планировщик записывает каждый шаг воронки** — день, вопрос «посмотрел?»,
  кнопки покупки — в таблицу `events`, а уход из бота — в `users.blocked_at`
  (написал боту снова — отметка снимается);
- **`/stats` открывает разделы кнопками**, нажатие правит то же сообщение
  (`bot/insights.py`):
  - *Сводка* — пришли (с разницей к прошлому такому же сроку), запустили,
    дошли до 2-го и 4-го дня, кнопки покупки, купили по продуктам, закрыли
    бота, писали в заботу, пришли по заявке с сайта; сколько идут марафон
    сейчас; лучший источник по доходимости и шаг с самой большой потерей;
  - *Воронка* — пришли → запустили → день 1…4 → кнопки → купили, с
    процентами, полосками и потерей на каждом шаге;
  - *Источники* — по каждой метке: пришли, запустили, дошли до 2-го и
    4-го дня, купили;
  - *Дни и опросы* — по каждому дню: получили, ответили «да» / «нет» /
    молчат, через сколько обычно отвечают; дни, ушедшие без записи;
  - *По времени* — последние 14 дней (пришли, запустили, дошли до 4-го,
    купили), часы и дни недели, когда приходят;
  - *Покупки* — по продуктам, конверсия из кнопок, путь от запуска до
    покупки, по источникам, последние покупки поимённо;
  - *Где люди сейчас* — на каком шаге каждый: смотрят отзывы, ждут вопроса,
    не ответили, ждут следующий день, прошли всё, закрыли бота;
- **выгрузка таблицей** — все люди: ник, имя, когда пришли и запустили,
  источник, докуда дошли, ответы, покупки, закрыли ли бота, где сейчас.

Команда проекта (ADMIN_IDS и STATS_IDS) в цифры не входит. Люди со ссылки
из заявки сайта (`?start=zayavka…`) марафон не запускают — ждут менеджера по
спортзалу, — поэтому в воронку марафона не входят и в сводке идут отдельной
строкой, а в «Где люди сейчас» — своей графой. У начавших до 11.09.2026
путь восстановлен по ответам и очереди шагов — кто прошёл всё молча, там не
виден; об этом сказано под сводкой.

## Заявка с сайта: человек пишет первым

Павел 09.09.2026: «Некоторые не проваливаются в личку тг, сами не пишут.
Лёха сам пишет им, и его аккаунт ограничили».

Причина не в доставке заявок — они доходят. Дело в том, куда вела ссылка
после заявки: на личный аккаунт менеджера, а он открывается **пустым
чатом**. Подставить туда первую фразу телеграм не даёт (в WhatsApp даёт —
там всё работало). Человек видит пустой экран и уходит; менеджер пишет
первым незнакомому аккаунту — и телеграм ограничивает его за рассылку.

Поэтому с сайта после заявки с выбором «Telegram» человек попадает в
этого бота по ссылке `?start=zayavka<номер>`. Телеграм показывает ему
кнопку «Запустить» — одно нажатие, и **первое сообщение уже от
человека**. Дальше:

- марафон такому человеку **не** запускается: он оставил заявку на
  спортзал и ждёт менеджера, а не четыре дня видео;
- бот отвечает «заявка №57 принята, менеджер напишет сюда»;
- в чат поддержки (`SUPPORT_CHAT_ID`) падает «Заявка с сайта №57 —
  человек в боте» с его ником и id;
- менеджер отвечает **реплаем на это сообщение**, и ответ уходит человеку
  в бота — тем же мостом, что и служба заботы. Личный аккаунт менеджера
  при этом не участвует, ограничивать нечего.

Заодно это единственный способ узнать, сколько людей действительно
дошли до переписки: в `/stats` они видны строкой «Заявка с сайта».

Вернуть прежнее поведение — убрать атрибут `data-bot` у формы в
`gym-landing/index.html`.

## Служба заботы

Кнопка есть с первого экрана и не исчезает. Всё, что человек пишет боту,
падает в чат заботы; менеджер отвечает **реплаем** на это сообщение, и ответ
возвращается человеку в бот. Переписка целиком остаётся в одном чате и видна
команде — в личку менеджера ничего не уходит.

## Сборка записей дней: заставка и схема тонкого плана

**Вертикально, 9:16 (с 10.09.2026).** Запись Zoom — 640×360, и телефон
Павла в ней стоит полосой 204×360 по центру (x=218, одинаково во всех
днях). В боте на телефоне это играло узкой полоской посреди чёрного —
Павел: «люди смотрят хер пойми какие видео, маленькие». Поэтому:

```bash
python tools/days.py --9x16          # все дни → «Марафон записи/9x16»
python tools/days.py --9x16 2 4      # только выбранные
SRC="C:/Users/Sharp/Desktop/Марафон записи/9x16" bash tools/upload_days.sh 1 2 3 4
```

Полоса вырезается и растягивается на 720×1280 (crf 27; на 12 ядрах x264
идёт в десять раз быстрее реального времени, все дни — около сорока
минут). Заставки дней и так 9:16 — во весь кадр. На сессии с выключенной
камерой — вертикальная схема `media/intro/schema-9x16.png` (заказчик
10.09.2026, 939×1674, во весь кадр); нет файла — широкая `schema.png` по
ширине на размытом фоне. Обложки `coverN.jpg` при этом тоже вертикальные.
Отрезки сессий один раз найденные лежат в `9x16/segments.json` (ключ —
день, имя и размер исходника) и при пересборке не ищутся заново.

В бота файлы по 300–800 МБ можно залить двумя путями (Bot API с сервера
принимает только до 50 МБ):

- **руками** — отправить боту из Telegram Desktop видео с подписью
  `day1`…`day4`;
- **самим ботом** (10.09.2026, когда залить руками было некому):

  ```bash
  set TG_API_ID=…  &  set TG_API_HASH=…
  python tools/upload_days_bot.py            # или: … 2 4 — выбранные дни
  ```

  Бот входит по протоколу клиента (Telethon, предел 2 ГБ), отправляет
  запись админу, пересылает её через Bot API и из ответа берёт file_id.
  file_id ложатся в `media/days.json`; после коммита и деплоя бот при
  старте ставит их вместо старых и обновляет закреп-хранилище
  (`backup.apply_committed`). Каждый file_id применяется один раз: если
  потом залить день руками, следующий деплой его не перетрёт.
  TG_API_ID/TG_API_HASH — пара клиента Telegram, только переменными, в
  репозиторий не кладутся.

Плеер страницы `/marathon/N` на сайте сделан 9:16.

```bash
python tools/days.py          # все четыре дня
python tools/days.py 2        # только второй
bash tools/upload_days.sh 1 2 3 4   # выложить на VPS, с докачкой
```

В начало каждой записи вшивается заставка дня от заказчика
(`media/intro/day1-4.mp4`, вертикальная — в горизонтальный кадр ложится
целиком, по бокам её же размытый кадр), а на время сессии — схема тонкого
плана (`media/intro/schema.png`). «Чёрный экран» сессии на самом деле —
серая заглушка зума: Павел выключает камеру на 18–25 минут. Скрипт находит
её сам, по ровному серому цвету над головой Павла, и кладёт схему ровно на
этот отрезок с плавным появлением; хвосты короче минуты (камера выключена
после прощания) не трогает.

Исходники зума 640×360, а на схеме и заставке мелкий текст, поэтому
собирается в 1280×720 — запись растягивается (телефон растянул бы её всё
равно), текст остаётся чётким. Один проход x264, около 4 МБ на минуту, час
записи считается минут семь. Заставки у заказчика записаны тихо — каждая
подтягивается по пику к −6 дБ, вровень с речью.

Готовые файлы — `Desktop/Марафон записи/День N.mp4`; на VPS они лежат в
`/var/lib/gym/marathon/dayN.mp4` и отдаются страницами сайта (см. ниже).
Скрипт выкладки шлёт хвост файла через ssh и при обрыве связи продолжает
с того же байта, готовый файл подменяет одним `mv`.

## Деплой на Railway

Репозиторий: https://github.com/kbeautyg/botmarafon

1. New Project → Deploy from GitHub repo → `kbeautyg/botmarafon`.
2. **Подключить диск**: Settings → Volumes → Add volume, точка монтирования
   `/data`. Без него база живёт до первого перезапуска, а вместе с ней —
   очередь отложенных шагов и запомненные записи дней. Бот сам увидит `/data`
   и положит базу туда. Если диска нет, бот скажет об этом админам при старте
   и в `/status` («База не на диске»).
   Записи дней и отзывы-картинки бот дублирует в закреплённое сообщение у
   каждого админа (`#хранилище`) и после переезда контейнера возвращает сам —
   закреп не откреплять. Очередь шагов так не спасти, диск всё равно нужен.
   Ещё одна страховка — переменные `DAY1`…`DAY4` (file_id видео или ссылка):
   их бот берёт, когда в базе пусто. file_id бот показывает в ответе на
   загрузку записи, пока база не на диске.
3. Переменные (Variables):

```
BOT_TOKEN=<токен от @BotFather>
CARE_CONTACT=Metod_Finish_Official
PURCHASE_CHAT_ID=<чат заявок>
ADMIN_IDS=<id админов через запятую>
STATS_IDS=<кому открыта только статистика, необязательно>
STATS_CHAT_ID=<чат почасовой сводки по источникам, необязательно>
ENTRY_CHAT_ID=<чат, куда сразу прилетает каждый вход в бота; пусто — STATS_CHAT_ID>
```

`SUPPORT_CHAT_ID` — только если заведут группу поддержки; кнопка заботы
работает и без неё, она ведёт прямо в аккаунт из `CARE_CONTACT`.

Дальше деплой идёт сам на каждый push в `main`. Пока диска нет, **каждый
push стирает базу** — людей и очередь шагов, — поэтому в `main` пушим
только то, что нужно самому боту, и не в разгар потока.

**VPS энергетического спортзала (91.230.94.147) для бота не годится:** с
него `api.telegram.org` не открывается вовсе — TCP-соединение по IPv4 висит
до таймаута, IPv6 у сервера нет. 3–4 сентября бот там сутки писал в журнал
«Failed to fetch updates» и не увидел ни одного человека; служба
`marathon-bot` на VPS остановлена и выключена из автозапуска. Записи дней
на этом VPS лежат и отдаются нормально — блокировка только на исходящие
соединения к Telegram.

**Важно:** телеграм отдаёт обновления одному слушателю. Пока бот работает
на Railway, локальный запуск надо погасить, иначе они будут перебивать друг
друга и часть сообщений людям не дойдёт.
